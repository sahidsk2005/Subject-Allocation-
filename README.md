# University Subject Allocation System

A desktop-based **University Subject Allocation System** developed as an academic project at **Brainware University**. The application helps manage student records, available subjects, student subject preferences, automatic subject allocation, and allocation reports.

## Overview

The system provides a graphical interface for managing students and subjects. Students can be assigned subject preferences in priority order. The application then runs an allocation process that considers each subject's available capacity and configured prerequisite.

The project is intended as an academic demonstration of Python GUI development and database operations.

## Features

- **Dashboard:** Displays the total number of students, subjects, and allocations.
- **Student Management:** Add student records with roll number, name, department, and semester.
- **Subject Management:** Add subjects with subject code, name, department, semester, capacity, and an optional prerequisite.
- **Preference Management:** Record a student's subject choices with a preference order.
- **Automatic Allocation:** Processes preferences in ascending preference order and checks subject capacity and the configured prerequisite rule.
- **Allocation Results:** View the generated allocation records.
- **Allocation Reset:** Clear existing allocation records and run the allocation process again.
- **Reports:**
  - Overall allocation summary
  - Subject occupancy report
  - Student allocation report

## How to Run the Project

### 1. Download or clone the repository

```bash
git clone https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
```

Or download the repository as a ZIP file and extract it.

### 2. Open the project folder

Open a terminal or command prompt in the folder containing `subject_allocation.py`.

### 3. Run the application

```bash
python subject_allocation.py
```

On some Windows installations, use:

```bash
py subject_allocation.py
```

The application window should open with the title **University Subject Allocation System**.

### 4. Start using the application

1. Open the **Students** tab to add or review student records.
2. Open the **Subjects** tab to add or review available subjects.
3. Open **Preferences** to select a student, choose a subject, and enter a preference order.
4. Open **Allocation** and click **RUN AUTOMATIC ALLOCATION**.
5. Open **Reports** to generate allocation summaries and occupancy reports.

## Database Structure

The application uses an SQLite database named `subject_allocation.db`. It creates the following four main tables:

| Table | Purpose |
|---|---|
| `students` | Stores student details such as roll number, name, department, and semester. |
| `subjects` | Stores subject details, capacity, semester, and prerequisite code. |
| `preferences` | Stores each student's selected subjects and preference order. |
| `allocations` | Stores the subject allocation records generated by the application. |

### Sample Data

On startup, the program inserts a small sample set of students and subjects. Existing records with duplicate student roll numbers or subject codes are skipped. You can also add your own records through the application.

## How the Allocation Process Works

1. The application clears the previous allocation records when a new allocation run begins.
2. It reads the registered students in database ID order.
3. For each student, it retrieves their preferences in ascending preference order.
4. Before allocating a subject, it checks whether the subject has reached its capacity.
5. If a prerequisite is configured and the prerequisite subject exists, the current implementation checks whether that student has added the prerequisite subject to their preferences.
6. If the checks pass, the allocation record is inserted into the database.
7. The allocation table and dashboard are refreshed.

**Academic project limitation:** The current prerequisite check uses the student's preference list as a proxy; it does not verify whether the prerequisite subject was actually completed in a previous semester. The current implementation can also allocate more than one subject to a student if multiple preferences pass the checks. These rules can be extended according to the university's actual allocation policy.
